# 触摸板修饰键：按住触摸板 + 长按按键 → 连发

状态：**Phase 2 需求草案**。Phase 0（XUSB 枚举/握手）硬件验收通过前不写代码，
音频改造与映射也都不启动。

## 1. 需求

触摸板点击不作为普通按键上报，而是当成一个“修饰键”：

> 按住触摸板，再长按某个按键 → 该键进入连发（auto-repeat）。

## 2. 已确认语义

- **触发**：触摸板按住期间，目标键连续按住 ≥ `TURBO_ARM_MS = 400 ms` 后进入连发；
  不足 400 ms 时保持普通的“实按”，短按不会被吞。
  - 计时起点：`max(按键按下时刻, 触摸板按下时刻)`。即先按住 A 再按触摸板，也从
    触摸板按下开始计 400 ms，避免“按住 A 再碰触摸板”瞬间触发。
- **连发频率**：15 Hz（周期 66 ms：33 ms 按下 / 33 ms 抬起）。
- **参与按键**：A/B/X/Y + LB/RB，对应 DS4 的 Cross/Circle/Square/Triangle + L1/R1。
  Guide、Start、Back、十字键、L3/R3 不参与 v1。
- **退出**：松开目标键或松开触摸板，立即回到“实按/松开”的普通语义，不残留。
- **触摸板点击本身不上报**：XInput 20B 报告里没有触摸板字段，天然无冲突。

## 3. 为什么只做 XINPUT persona

DS4 persona 的目标是“字节透传”：触摸板点击是 USB 报告 0x01 状态块里的真实字段
（`DS4_PAYLOAD_BTN_PS` bit1），拦掉它会破坏与真机 DS4 的一致性；连发还要重写
HID 输入报告，属于另一套逻辑。XInput 报告没有触摸板位，触摸板只能当修饰键，
正好是这块功能最干净的落点。

## 4. 实现落点（Phase 2）

- 映射层直接消费 `on_hid_input()` 已经解析好的 63 字节 DS4 状态块，不重新解析 BT 报文。
- 连发判定写成**纯函数**（输入：按键掩码、触摸板状态、`now_ms`；输出：本帧有效按键掩码），
  放独立头文件、不依赖 SDK —— 与 `spk_recovery_policy.h` 同一种做法，便于 host 单测。
- 节拍沿用 Phase 2 的固定 4 ms 输入报告；连发相位由 `now_ms` 推导
  （`(now_ms / half_period) & 1`），不额外开定时器。
- 每键状态只需 `pressed / arm_since_ms / turbo_active`，6 个键，RAM 可忽略。
- 连发只改“按下/抬起”的时序，不碰扳机模拟量、摇杆、震动、LED。

## 5. 边界条件

| 场景 | 行为 |
|---|---|
| 触摸板未按 | 完全直通，连发状态清零 |
| 按住触摸板 + 短按目标键 | 普通按键（不足阈值，不吞掉短按） |
| 连发中松开触摸板 | 目标键恢复为实按（仍按住）或松开，不继续脉冲 |
| 连发中松开目标键 | 立即停止并清状态 |
| 同时两个目标键 | 各自独立计时/相位（相位可共用，实现更简单） |
| Guide | 永不参与（长按会触发主机侧语义） |

## 6. 验收

- host 单测：阈值前直通、阈值后 15 Hz 波形、松手复位、触摸板未按不连发、
  短按不被吞。
- 真机（Phase 2）：`joy.cpl`/XInput 工具里按住触摸板 + 长按 A 能看到周期性按下；
  普通按键不受影响。
